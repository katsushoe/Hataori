# Hataori 3.0.3.0 MSI実機検証結果

## 実施日

2026-08-17

## 成果物

- MSI: `Hataori-3.0.3.0-x64.msi`
- SHA-256: `72BDF90296AA8A36DE7ECD41C3E050DE548111864BB146B6DA8DFE90416E59BB`
- WiX Toolset 5.0.2
- win-x64 self-contained single-file

## 変更内容

- MCP読み取り専用ツール`get_version`を追加（サーバー名・バージョンを返す）。`tool_count`が11から12へ変化。
- Windows InstallerはProduct Versionの4番目を Upgrade比較に使わないため（`2026-08-17-installer.md`参照）、3番目を増加させ3.0.2.0→3.0.3.0とした。

## 合格

- `dotnet build` / `dotnet test`: 警告0、エラー0、全125件のテスト合格
- WiX ICE検証、警告0、エラー0でのMSIビルド
- 管理者権限での`msiexec /i`によるMajor Upgrade（`F:\Hataori`、Exit Code 0）
- Upgrade後の`hataori version` → `3.0.3.0`
- Upgrade後のService再起動（Stopped→Running、管理者権限で`Start-Service`）
- `hataori mcp status` → `connected: true`、`tool_count: 12`
- `tools/call`による`get_version`の実呼び出し → `{"name":"Hataori","version":"3.0.3.0"}`
- `hataori doctor`（管理者権限） → `server`／`itoguruma`／`mcp`／`sqlite`／`claude_cli`／`windows_service`／`hooks`／`configuration`はすべて`ok: true`

## 既知の未解消事項（今回のリリースと無関係）

- `hataori doctor`の`codex_cli`チェックが失敗（`codex`コマンドが本機PATH上に見つからない）。本機にCodex CLIが未導入／未PATH登録という既存の環境要因であり、今回のバージョンアップに起因する退行ではない。

## 未実施

- Uninstall検証: `F:\Hataori`が本機の実運用環境（本検証セッションのMCP接続先を含む）であるため、今回はUninstall実機検証を意図的に省略した。次回、実運用に影響しない検証環境で実施する。
